# 06. dp_step4b_upstream.m 해설

> 담당: B   대상 파일: `dp/dp_step4b_upstream.m` (130줄)   관련 결과 폴더: `out/dp_step4b_upstream/` (key_upstream.json, methods.csv, summary.txt, results.mat, run_info.txt)

이 파일은 `dp/dp_step4_realistic.m`(05번 문서)을 거의 그대로 복사한 뒤, **관측창(위성이 관측을 시작·종료하는 위경도 상자)만 임무 관측창으로 바꾼** 것이다. 그래서 이 문서는 "step4와 같은 부분은 05번을 보고, 다른 부분만 자세히" 원칙으로 쓴다. 공용 함수(`kre_lib.m`)의 속은 01번 문서 몫이다.

## 1. 한 줄 역할
step1·step4가 만든 학습표(큐 강도 → 실제 호우 확률 표) 두 개와 IMERG 강수 자료(2023~2025 장마철)를 받아, **임무 관측창(북위 28~38°·동경 119~127°, 장마 상류 바다)** 안에서만 5가지 관측 방식의 호우 포착 수를 다시 세어 "천저 고정 대비 몇 배"를 만든다. 제안서의 대표 숫자(2024년 2.13배, 2025년 2.38배)가 여기서 나온다.

## 3. 절별 해설
(step4와 똑같은 줄은 05번 문서의 해당 절을 가리키고 넘어간다.)

### 3.1 준비: 관측창 덮어쓰기와 학습표 읽기 (줄 18~23)
```matlab
L = kre_lib();
P = L.params();
P.winLat = [28 38];  P.winLon = [119 127];       % 임무 관측창 (장마 상류 바다)
Pe = P;  Pe.pDet = 1;  Pe.posSd = 0;  Pe.velSd = 0;
S = load(fullfile(here, '..', 'out', 'dp_step1_train', 'calib_2023.mat'));         calibF = S.calibN;
S = load(fullfile(here, '..', 'out', 'dp_step4_realistic', 'calib_early_2023.mat')); calibE = S.calibE;
```
이 파일에서 **진짜로 새로운 줄은 20번 하나**다. `L.params()`가 돌려준 기본 관측창(서해~동해)을 임무 관측창으로 바꾼다. `winLat`은 [남쪽 끝, 북쪽 끝], `winLon`은 [서쪽 끝, 동쪽 끝] 순서다. 바로 다음 줄에서 `Pe = P`로 복사하므로 `Pe`도 새 창을 갖는다(복사 순서가 바뀌면 틀어질 수 있는데, 지금은 맞다). 학습표는 Final 큐용(`calibN`, step1)과 Early 큐용(`calibE`, step4)을 각각 다른 파일에서 읽어 이름을 `calibF`·`calibE`로 바꿔 둔다. 그래서 **이 파일을 돌리기 전에 step1과 step4를 먼저 돌려야** 한다.

### 3.2 방식 5개와 결과 그릇 (줄 25~31)
```matlab
years   = [2023 2024 2025];
methods = ["천저 고정", "기존 방식(Early 큐)", "DP 나우캐스트(Early 큐)", "DP 나우캐스트(Final 큐, 3단계)", "DP 완벽 정보(상한)"];
iMain = 3;
nY = numel(years);  nM = numel(methods);  nDay = 122;
tot  = zeros(nY, P.nPhase, nM, 3);              % [호우 프로파일, 강수 프로파일, 호우 세포]
dayH = zeros(nY, nDay, nM);
nPass = zeros(nY, P.nPhase);
```
방식은 step4의 7개 중 5개다. 1 = 천저만 보는 기준, 2 = 호우 점을 하나씩 찍는 기존 방식, 3 = **주 결과**(거친 Early 큐로 비를 따라가는 DP), 4 = 정밀 Final 큐 DP(3단계와 같은 조건, 낙관적), 5 = 미래를 다 아는 상한. `nDay = 122`는 6월 1일~9월 30일 날수(30+31+31+30)로 날짜 부트스트랩의 그릇 크기다. `tot`의 마지막 차원이 step4의 6에서 3으로 줄었다.

### 3.3 시즌 반복: 통과마다 5가지 계획 세우고 채점 (줄 33~63)
```matlab
passes = L.orbitPasses(Df, P, ip);              % ← P 안의 새 관측창으로 통과를 고른다
...
plans{1} = struct('cb', zeros(size(G.tq)), 'valid', true(size(G.tq)));            % 천저
plans{2} = L.greedyPlan(G, DfE, Pe, 'nowcast', RandStream('mt19937ar', 'Seed', seed));
[Rw, th] = L.rewardGrid(G, DfE, Pe, 'nowcast', RandStream('mt19937ar', 'Seed', seed), calibE);
plans{3} = L.dpPlan(Rw, th, P);                 % 주 결과: Early 큐 DP
[Rw, th] = L.rewardGrid(G, Df, P, 'nowcast', RandStream('mt19937ar', 'Seed', seed), calibF);
plans{4} = L.dpPlan(Rw, th, P);                 % Final 큐 DP (3단계 조건)
[Rw, th] = L.rewardGrid(G, Df, P, 'oracle', [], []);
plans{5} = L.dpPlan(Rw, th, P);                 % 완벽 정보 상한
```
구조는 05번 3절과 같다. 관측창이 쓰이는 곳은 `L.orbitPasses(Df, P, ip)` 한 군데다. 이 함수는 위성 궤도를 시즌 전체(5,856장면 × 30분)로 전파해 직하점이 `P.winLat`·`P.winLon` 안에 있는 연속 구간을 "통과" 하나로 자른다(01번 참고). 그 뒤의 계획 세우기(`rewardGrid`·`dpPlan`·`greedyPlan`)와 채점(`evaluate`)은 관측창을 보지 않고 통과 기하 `G`와 자료만 쓴다. 씨앗 규칙 `years*1e5 + ip*1e4 + kp`는 step4와 같지만, 통과 번호 `kp`가 새 창 기준으로 다시 매겨지므로 같은 물리적 통과가 step4와 같은 씨앗을 받는 것은 아니다. 다만 Early 큐 방식(2·3)은 `Pe.pDet = 1, posSd = 0, velSd = 0`이어서 난수가 결과에 아무 영향을 주지 않고, 씨앗이 실제로 작용하는 것은 가짜 큐 오차를 켠 방식 4뿐이다.

### 3.4 집계와 신뢰구간 (줄 65~77)
```matlab
mTot = squeeze(mean(tot, 2));                    % nY × nM × 3  (위상 8개 평균)
gain = mTot ./ mTot(:, 1, :);                    % 천저 고정 = 1
for iy = 1:nY
    rs = RandStream('mt19937ar', 'Seed', 300 + years(iy));
    X = squeeze(dayH(iy, :, :));                 % 122일 × 5방식
    bs = zeros(2000, nM);
    for b = 1:2000
        s = sum(X(randi(rs, nDay, nDay, 1), :), 1);
        bs(b, :) = s / s(1);
    end
    ci(iy, :, :) = reshape(prctile(bs, [2.5 97.5])', [1 nM 2]);
end
```
배수 = (그 방식의 시즌 호우 프로파일 수) ÷ (천저 고정의 수). 예: 2024년 Early 큐 DP 127.625 ÷ 천저 59.875 = 2.1315배(`methods.csv` 2024 행). 신뢰구간은 "122일 중 122일을 겹치게 다시 뽑아 더한 뒤 배수를 구하기"를 2000번 반복해 가운데 95%를 잡는다. step4의 날짜 부트스트랩이 씨앗 7 하나를 세 해가 이어 쓰는 것과 달리 여기서는 해마다 `300 + 연도`를 쓴다(5절 지적 5). 5일 묶음 부트스트랩과 Early÷Final 비는 뺐다.

## 4. 핵심 가정 3개
1. **학습표는 관측창과 무관하다** — `calibrate`는 자료 상자(동경 119~132°·북위 28~40°, `imerg/harmony_download.py` BOX) 전체 칸·전체 장면으로 "큐 x mm/h → 30·60분 뒤 호우 확률"을 세므로, 창을 바꿔도 다시 배울 것이 없다고 보았다. — 깨지면: 바다(관측창) 비와 육지(한반도) 비의 성질이 크게 다르면 표가 창 안 비에 살짝 안 맞을 수 있다. 다만 표는 "확률의 상대 크기"로 쓰여서(어느 각도가 더 유망한가), 절대값이 조금 틀려도 DP의 선택 순서는 거의 안 바뀐다.
2. **관측창 경계 = 자료 상자 경계(서·남쪽)** — 창의 서쪽 끝 119°E와 남쪽 끝 28°N이 내려받은 IMERG 상자의 끝과 같다. 빔을 ±10° 기울이면 지상에서 550 km × tan 10° ≈ 97 km(위도 약 0.88°, 경도 약 1.04°) 옆을 보는데, 창 서·남 가장자리에서 바깥으로 기울인 빔은 자료 밖이라 `sampleField`가 NaN을 주고 코드가 "비 없음"으로 처리한다. — 깨지면(즉 실제로는 거기 비가 있었다면): DP·상한·기존 방식의 호우 수가 조금 **적게** 세어진다(천저는 항상 창 안이라 영향 없음). 보수적 방향이라 제안서 숫자가 부풀려지지는 않는다(5절 지적 6).
3. **step4의 나머지 가정을 전부 물려받는다** — 큐 = IMERG Early(거친 빠른판), 채점 = Final(정밀판), 2023으로 배우고 2024·2025로 검증, 큐 지연 15분, 정착 4초, ±10°, 궤도 위상 8개. Early가 실제로는 약 4시간 뒤 나오는 자료라는 점, Early와 Final이 입력을 일부 공유해 독립 큐(천리안 2A)보다 낙관적일 수 있다는 점도 그대로다. — 깨지면: 05번 4절 참고.

## 7. 본선 예상 질문 3개와 답
**Q1.** 관측창을 좁히니 이득이 2.0배에서 2.1~2.4배로 커졌는데, 유리한 곳만 고른 것 아닌가요?
**A.** 창은 모의 뒤에 고른 것이 아니라 임무 정의(장마 상류 바다)에서 먼저 정해져 있었고, 넓힌 해역 결과(약 2.0배)도 제안서에 함께 적었습니다. 임무 창은 천저에 걸리는 호우가 통과당 0.25개로 넓힌 해역(0.42개)보다 적어, 비가 드물고 뭉쳐 있을수록 "골라 보는" 이득이 커지는 자연스러운 결과입니다. 창의 서·남 경계가 자료 경계여서 바깥으로 기울인 빔은 비 없음으로 처리되므로, 오히려 조금 보수적으로 센 값입니다.

**Q2.** 학습표를 넓은 해역에서 만든 것을 그대로 쓰면 좁은 창에 맞지 않는 것 아닌가요?
**A.** 학습표는 관측창이 아니라 내려받은 자료 상자 전체(동경 119~132°·북위 28~40°)의 모든 칸으로 "큐 x mm/h가 30분 뒤 실제 호우일 확률"을 센 것이어서 창 설정과 무관합니다. 또 2023년으로만 배우고 2024·2025년에 그대로 적용했으므로 검증 해의 정답을 본 것도 아닙니다. 표는 어느 각도가 더 유망한지 순서를 매기는 데 쓰여, 절대값이 조금 달라도 DP의 선택은 거의 바뀌지 않습니다.

**Q3.** 2.13배·2.38배의 신뢰구간이 1.8~3.0배로 넓은데, 그래도 2배라고 말할 수 있나요?
**A.** 신뢰구간은 장마철 122일을 다시 뽑아 2000번 계산한 범위이고, 하한이 1.83(2024)·1.93(2025)으로 두 해 모두 1보다 훨씬 위에 있어 "천저보다 낫다"는 결론은 흔들리지 않습니다. 폭이 넓은 것은 호우가 며칠에 몰리는 장마의 성질 때문이며, 정밀 큐(Final)를 쓰면 2.85·3.10배, 미래를 다 알아도 4.6·5.3배가 상한입니다. 제안서는 그래서 "약 2배"라는 보수적 표현을 썼습니다.
