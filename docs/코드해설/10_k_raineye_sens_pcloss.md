# 10. k_raineye_sens_pcloss.m 해설

> 담당: C   대상 파일: `matlab/k_raineye_sens_pcloss.m` (87줄)   관련 결과 폴더: `matlab/out/sens_pcloss/` (summary.txt, key_sens_pcloss.json, run_info.txt) + `matlab/out/run_log.csv`에 한 줄

## 1. 한 줄 역할
09번(`k_raineye_analysis.m`)이 "펄스압축 손실 0"으로 계산했던 감도(레이더가 잡을 수 있는 가장 약한 비, 단위 dBZ) 16가지 조합과 "Ka 전파가 비에 먹혀 못 보는 맨 아래 높이"를, 채택 파형의 펄스압축 손실 1.49 dB(`matlab/out/key_nlfm.json`)를 더한 10.5 dBZ 기준으로 다시 계산해 제안서 숫자(14/16 조합 통과, 최악 14.5 dBZ, 20 mm/h 1.1 km, 30 mm/h 1.95 km)를 만든다.

## 3. 절별 해설

### 3.1 준비와 채택 파형 손실 읽기 (줄 9~20)
```matlab
K = jsondecode(fileread(fullfile(here, 'out', 'key_nlfm.json')));
iDes = find(strcmp(K.designs, 'LFM 테이퍼 + 부정합 필터'));
lossPC = K.loss(1, iDes);     % 채택안 손실 [dB] (설정 1: 166 µs, 0.5 m)
Zadopt = K.Zmin(1, iDes);     % 채택안 감도 [dBZ] (제안서 10.5 dBZ)
```
`key_nlfm.json`은 09번 14절(펄스압축 파형 비교)이 남긴 결과다. `K.loss`는 4행(설정: 166 µs·0.5 m, 166 µs·1 m, 83 µs·0.5 m, 83 µs·1 m) × 5열(파형 설계) 표이고, 채택안은 5번째 열 'LFM 테이퍼 + 부정합 필터'다. 1행 5열을 읽으면 `lossPC` = 1.4854 dB, `Zadopt` = 10.5209 dBZ(`matlab/out/key_nlfm.json`의 `loss[0][4]`, `Zmin[0][4]`).

펄스압축(긴 펄스를 쏘고 받은 뒤 짧게 눌러 거리 분해능을 얻는 기법)에서 "테이퍼(펄스 양 끝을 부드럽게 줄임)"와 "부정합 필터(부엽을 줄이려고 일부러 최적이 아닌 필터를 씀)"를 쓰면 신호 대 잡음비가 조금 손해 본다. 그 손해가 1.49 dB이고, 이 파일은 그 값을 모든 감도에 더한다. 손실 자체가 어떻게 나왔는지는 09번 3.x절(14절 NLFM 설계) 몫이다.

### 3.2 레이더 방정식 비율의 재료 (줄 22~31)
```matlab
c0 = 299792458;  fRad = 35.75e9;  lam = c0 / fRad;
Vg   = C.Re * sqrt(C.mu / (C.Re + O.h)^3);   % 지상 궤적 속도 [km/s]
fpKm = 2 * O.h * tand(1.13 / 2);             % 풋프린트 지름 [km]
Tfp  = fpKm / Vg;                            % 풋프린트 통과 시간 [s]
Ref.R = 400;  Ref.PRF = 1 / 1660e-6;  Ref.B = 2.5e6;  Ref.Zs = [11.0 13.0];
Ref.Ts = [0.28, 7.9 / (C.Re * sqrt(C.mu / (C.Re + 400)^3))];
ant.bw = [1.13, 70 * lam / 1.0];  ant.G = [42.6, 49.2];
ant.dG = 2 * (ant.G - ant.G(1)) + 20 * log10(ant.bw / ant.bw(1));
PRFk = [1500 1800];  Bnew = 1.2e6;
```
이 파일은 레이더 방정식을 처음부터 풀지 않는다. 대신 **"RainCube(NASA JPL의 6U 큐브위성 강수레이더)가 400 km 궤도에서 실제로 잰 감도 11.0 dBZ"를 출발점으로 두고, 우리와 달라지는 것만 비율로 더하고 뺀다.** 그래서 "기준(Ref)"과 "우리 값"이 짝으로 나온다.

- `lam` = 0.00839 m(8.4 mm). 파장(전파 한 번 진동하는 길이) = 빛의 속도 ÷ 주파수.
- `Vg` = 6.98 km/s. 위성이 지면 위를 지나가는 속도. 케플러 식 √(μ/r³)에 지구 반지름을 곱한 값.
- `fpKm` = 2 × 550 × tan(0.565°) = 10.85 km. 빔폭 1.13°가 550 km 아래 땅에 그리는 원(풋프린트)의 지름.
- `Tfp` = 10.85 ÷ 6.98 = 1.55 s. 한 지점이 빔 안에 머무는 시간 = 적분(여러 펄스를 합쳐 평균) 가능한 시간.
- `Ref.Ts` = [0.28, 1.095] s. RainCube가 몇 초를 평균했는지 공개 자료가 없어 "짧게 0.28 s"와 "풋프린트 7.9 km 통과 시간(7.9 ÷ 7.22 km/s = 1.095 s)" 두 가지를 다 둔다.
- `ant.dG(2)` = 2 × (49.2 − 42.6) + 20·log10(0.587 / 1.13) = 13.2 − 5.69 = **7.51 dB**. 1 m 안테나를 쓰면 이득(안테나가 전파를 한 방향으로 모으는 정도)이 6.6 dB 올라가는데 송신·수신 두 번 적용돼 13.2 dB. 하지만 빔이 좁아져(0.587°) 비추는 비의 부피가 줄어드니 20·log10(빔폭비) = −5.69 dB를 돌려준다. 결국 7.51 dB만큼 더 약한 비를 본다.

### 3.3 레이더 방정식 비율 — 한 항씩 (줄 38~39)
```matlab
d = 20 * log10(O.h / Ref.R) - 5 * log10(pf / Ref.PRF) - 5 * log10(Tfp / tr) - ant.dG(ia);
if ub, d = d + 5 * log10(Bnew / Ref.B); end
sens(end + 1, :) = [zr, tr, pf, ub, ia, zr + d];
```
감도(dBZ)는 "작을수록 좋다"(더 약한 비를 본다). `d`는 기준 감도에 더하는 보정량이고, 양수면 나빠지고 음수면 좋아진다. dB(데시벨)는 비율을 10·log10으로 적은 것이라, 곱셈이 덧셈이 된다. 전력이 2배면 +3 dB, 10배면 +10 dB. 중심 조합(기준 11 dBZ, 기준 적분 1.095 s, PRF 1800, 대역 보정 있음, 0.5 m)으로 숫자를 넣어 보자.

| 항 | 코드 | 왜 이 계수인가 (고등학생용) | 중심 조합 값 |
|---|---|---|---|
| 거리 | `+20·log10(550/400)` | 전파가 멀리 갈수록 되돌아오는 세기는 거리의 제곱에 반비례(1/R²). 제곱이라 10·log10이 두 배인 **20**·log10. 550 km는 400 km보다 1.375배 멀어 신호가 1.89배 약해진다 | +2.77 dB (나빠짐) |
| PRF | `−5·log10(PRF/602.4)` | PRF(초당 펄스 수)가 높으면 같은 시간에 더 많은 독립 표본을 평균한다. 잡음은 N개 평균하면 √N만큼 줄어서, 전력으로 10·log10(√N) = **5**·log10(N). 기준은 RainCube 펄스 간격 1660 µs → 602 Hz | PRF 1800: −2.38 dB (좋아짐). PRF 1500: −1.98 dB |
| 적분 시간 | `−5·log10(Tfp/tr)` | 같은 이유. 우리 풋프린트 통과 1.55 s를 기준 적분시간으로 나눈 비율만큼 표본 수가 늘어난다. 역시 √N 효과라 **5**·log10 | 기준 1.095 s: −0.76 dB. 기준 0.28 s: −3.72 dB |
| 대역 | `+5·log10(1.2/2.5)` (보정 '유'일 때만) | 대역폭 B(펄스압축 후 거리 분해능을 정하는 폭)를 2.5 MHz → 1.2 MHz로 줄이면 수신기 잡음 전력이 B에 비례해 줄어(10·log10, 좋아짐) 대신 250 m 출력 칸 안에 들어가는 독립 거리 표본이 B에 비례해 줄어(5·log10, 나빠짐). 합치면 **+5**·log10(B/B₀)이고 B/B₀ = 0.48이라 음수 → 좋아진다. '무'는 이 효과를 믿지 않는 보수적 선택 | 유: −1.59 dB. 무: 0 |
| 안테나 | `−ant.dG(ia)` | 3.2절의 7.51 dB. 0.5 m이면 0 | 0.5 m: 0. 1 m: −7.51 dB |

중심 조합: 11.0 + 2.77 − 2.38 − 0.76 − 1.59 = **9.04 dBZ** (`key_sens_pcloss.json`의 `Zcentral` 9.0355). 여기에 손실 1.49를 더하면 10.52 dBZ = `Zadopt`. 제안서의 "약 10.5 dBZ"가 이 숫자다.

### 3.4 16가지 조합은 무엇의 곱인가 (줄 32~45)
```matlab
for zr = Ref.Zs            % 기준 반사도 11 / 13 dBZ
    for tr = Ref.Ts        % 기준 적분시간 0.28 / 1.095 s
        for pf = PRFk      % PRF 1500 / 1800 Hz
            for ub = [1 0] % 대역 보정 유 / 무
                for ia = 1:2   % 안테나 0.5 m / 1 m
```
"16가지"는 **불확실한 가정 네 가지를 각각 두 값으로 둔 2⁴ = 16**이다. 안테나는 가정이 아니라 설계 대안이라 따로 세어 `sens`는 32행이 된다(summary.txt의 조합 1~32).

| 선택 | 값 A (유리) | 값 B (불리) | 감도 차이 | 뜻 |
|---|---|---|---|---|
| 기준 반사도 `zr` | 11.0 dBZ (RainCube 궤도 실측) | 13.0 dBZ (eoPortal·WMO 표기) | 2.0 dB | 출발점 자체를 얼마나 믿나 |
| 기준 적분시간 `tr` | 0.28 s (짧게 평균했다고 봄 → 우리 1.55 s가 크게 유리) | 1.095 s (풋프린트 통과 시간만큼 평균했다고 봄) | 3.72 − 0.76 = 2.96 dB | RainCube가 몇 펄스를 평균했는지 모름 |
| PRF `pf` | 1800 Hz | 1500 Hz | 0.40 dB | 우리 운용 범위 1.5~1.8 kHz(09번 10절) |
| 대역 보정 `ub` | 유(−1.59 dB) | 무(0) | 1.59 dB | 좁은 대역의 잡음 이득을 믿나 |

네 가지가 모두 유리하면 11 + 2.77 − 2.38 − 3.72 − 1.59 + 1.49 = **7.56 dBZ**(조합 5), 모두 불리하면 13 + 2.77 − 1.98 − 0.76 + 0 + 1.49 = **14.51 dBZ**(조합 27). 그래서 "7.6 ~ 14.5 dBZ"다. 네 선택의 합이 큰 순서로 늘어놓으면 13 dBZ를 넘는 것은 "13 dBZ + 1.095 s + 보정 무"에 PRF 1500(14.51)과 1800(14.11)의 두 가지뿐이고, 나머지 14가지가 13 이하다(summary.txt 조합 27, 31).

### 3.5 중심 조합 고르기, 손실 더하기, 자기 검사 (줄 46~50)
```matlab
isCentral = sens(:, 1) == 11 & abs(sens(:, 2) - Ref.Ts(2)) < 1e-9 & sens(:, 3) == 1800 & sens(:, 4) == 1 & sens(:, 5) == 1;
Zc = sens(isCentral, 6);
s05 = sens(sens(:, 5) == 1, 6) + lossPC;   % 0.5 m 16개 + 손실
s10 = sens(sens(:, 5) == 2, 6) + lossPC;   % 1 m 16개 + 손실
assert(abs(Zc + lossPC - Zadopt) < 0.05, '중심값 + 손실이 채택안 감도와 다르다');
```
다섯 조건을 모두 만족하는 행은 하나뿐이어서(조합 13) `Zc`는 숫자 하나가 된다. 적분시간은 소수라 `==` 대신 "차이가 10⁻⁹보다 작다"로 비교한다. `assert`는 "09번 8절의 중심값 + 09번 14절의 손실 = 09번 14절의 채택 감도"가 맞는지 스스로 확인하는 안전장치다. 09번 14절은 감도를 `Zc + 손실`로 정의했으므로 두 파일이 같은 입력을 썼다면 차이는 0에 가깝다(실제 차이는 10⁻¹⁵ dB 수준, 5절 지적 4 참고).

### 3.6 감쇠로 못 보는 맨 아래 높이 (줄 52~56, 84~87)
```matlab
kR = 0.3452;  aR = 0.8851;  Rr = [5 10 20 30 50];  Hr = 4.5;
gam = kR * Rr.^aR;  hg = (0:0.05:Hr)';  Ztrue = 10 * log10(200 * Rr.^1.6);
lowestAt = @(Zth) arrayfun(@(k) firstVis(Ztrue(k) - 2 * gam(k) * (Hr - hg), Zth, hg, Hr), 1:numel(Rr));
low90 = lowestAt(Zc);  low105 = lowestAt(Zadopt);

function h = firstVis(Zm, Zth, hg, Hr)
vis = Zm >= Zth;
if any(vis), h = hg(find(vis, 1)); else, h = Hr; end
end
```
Ka 대역(35.75 GHz) 전파는 빗방울에 많이 흡수된다. 식은 세 개다.

1. **비감쇠** γ = k·R^a [dB/km, 한 방향]. ITU-R P.838-3(국제전기통신연합의 강우 감쇠 표)에서 35.75 GHz 연직 편파 계수 k = 0.3452, a = 0.8851. 20 mm/h면 γ = 0.3452 × 20^0.8851 = 0.3452 × 14.17 = **4.89 dB/km**.
2. **진짜 반사도** Ztrue = 10·log10(200·R^1.6) (Marshall–Palmer 관계: 비 세기 R[mm/h]를 반사도 Z[mm⁶/m³]로 바꾸는 경험식). 20 mm/h면 10·log10(200 × 120.6) = 10·log10(24,125) = **43.8 dBZ**.
3. **위성에서 보이는 반사도** Zm(h) = Ztrue − 2·γ·(Hr − h). 비는 지상 0 km부터 액상층 꼭대기 Hr = 4.5 km까지 있고, 위성 전파는 위에서 내려와 높이 h까지 (Hr − h) km를 비 속으로 뚫고 갔다가 되돌아오므로 **왕복 2배**. 땅(h = 0)에서는 43.8 − 2 × 4.89 × 4.5 = 43.8 − 44.0 = **−0.2 dBZ**로 감도 10.5보다 훨씬 작아 안 보인다.

`firstVis`는 높이 격자 `hg`(0, 0.05, 0.10, …, 4.5 km)를 아래부터 훑어 Zm ≥ 감도가 처음 되는 높이를 돌려준다. 20 mm/h에서 식으로 풀면 h* = 4.5 − (43.8 − 10.52) / (2 × 4.89) = 4.5 − 3.40 = 1.097 km이고, 그 위 첫 격자가 **1.10 km**. 30 mm/h는 γ = 7.01, Ztrue = 46.6, h* = 1.922 → **1.95 km**. 5·10 mm/h는 땅에서도 각각 21.3·15.2 dBZ가 남아 0 km(다 보임). 어떤 높이에서도 안 보이면(`any(vis)`가 거짓) Hr을 돌려주는데, 꼭대기 h = Hr에서는 감쇠가 0이라 Ztrue ≥ 감도면 반드시 보이므로, 이 경우는 "비 자체가 감도보다 약한 때"뿐이고 지금 입력(Ztrue 34~50 dBZ)에서는 일어나지 않는다. 식은 09번 9절과 같고 감도만 Zc 대신 Zadopt를 넣은 것이다(09번 3.x절 참고).

key = struct('lossPC', lossPC, 'Zadopt', Zadopt, 'Zcentral', Zc, 'range05', [min(s05) max(s05)], 'meet13_05', mean(s05 <= 13), ...

`summary.txt`에는 사람이 읽을 문장 5줄과 32행 표, `key_sens_pcloss.json`에는 다른 프로그램(결과보고 생성기 `tools/make_report.py`)이 읽을 숫자, `run_info.txt`에는 실행 시각·경로·MATLAB 판, `out/run_log.csv`에는 "시각, 스크립트, 결과 폴더, 한 줄 메모"를 덧붙인다(프로젝트 규칙: 모든 MATLAB 실행은 결과 폴더를 남기고 run_log에 한 줄 추가). `nnz(s05 <= 13)`는 "13 이하인 개수"(nnz = 0이 아닌 원소 수), `mean(s05 <= 13)`은 그 비율(14/16 = 0.875)이다.

## 4. 핵심 가정 3개
1. **감도는 RainCube 실측 11.0 dBZ(400 km)에서 비율로만 바뀐다** — 송신 전력, 펄스폭(166 µs), 잡음 지수 같은 하드웨어는 RainCube급이라고 보고 궤도·PRF·적분·대역·안테나 차이만 넣었다. 깨지면(예: 우리 송신기가 RainCube보다 약하면) 16가지 전부가 같은 양만큼 평행 이동한다. 그래서 출발점 자체의 불확실성을 "13 dBZ 기준" 여덟 가지로 함께 넣어 두었다.
2. **펄스압축 손실 1.49 dB는 RainCube 실측 위에 따로 더한다** — RainCube의 11.0 dBZ에는 RainCube 자신의 파형 손실이 이미 들어 있을 텐데, 그 값을 모르니 0으로 보고 우리 손실을 통째로 더했다. 보수적(실제보다 나쁘게 보는) 가정이라, 깨져도 감도는 좋아지는 쪽이다.
3. **비는 0~4.5 km 액상층에 같은 세기로 꽉 차 있고, 그 위에서는 감쇠가 없다** — 장마철 영점층(0 °C 높이) 약 4.5 km를 썼다. 실제 비는 높이에 따라 세기가 바뀌고 영점층 위 얼음은 감쇠가 작다. 층이 더 두껍거나 비가 더 세면 못 보는 높이가 올라가고, 비가 고르지 않으면(위는 약하고 아래만 셈) 내려간다. 또 Marshall–Palmer는 Ka 대역의 비레일리 효과(빗방울이 파장 8 mm에 견줘 커서 산란이 단순 비례에서 벗어남)를 반영하지 않는다.

## 7. 본선 예상 질문 3개와 답
**Q1.** 13 dBZ 목표를 못 맞추는 2가지 조합은 무엇이고 어떻게 할 건가요?
**A.** 둘 다 "RainCube 기준을 보수적인 13 dBZ로 잡고, RainCube가 풋프린트 통과 시간(1.1 s)만큼 충분히 평균했다고 보고, 좁은 대역의 잡음 이득도 안 믿는" 가장 불리한 가정의 묶음으로, PRF 1500에서 14.5 dBZ, 1800에서 14.1 dBZ입니다(summary.txt 조합 27, 31). 대책은 1 m 전개 안테나 대안(7.5 dB 개선, 그 경우 최악 7.0 dBZ)이고, 그 전에 궤도 초기 90일 검증에서 해면 반사로 실제 감도를 재어 어느 조합이 현실인지 확인합니다. 이 두 조합도 15 dBZ급 비(약 0.3 mm/h)는 보므로 호우 관측 임무 자체는 성립합니다.

**Q2.** RainCube 실측 11 dBZ에는 이미 그 레이더의 파형 손실이 들어 있을 텐데, 우리 손실 1.49 dB를 또 더하면 이중으로 깎는 것 아닌가요?
**A.** 맞습니다. RainCube의 파형 손실 값을 공개 자료에서 찾지 못해 0으로 두고 우리 손실을 통째로 더했으니, 그만큼 실제보다 나쁘게 본 보수적 추정입니다. 그래서 제안서 대표값 10.5 dBZ는 "적어도 이 정도"라는 뜻이고, 손실 전 9.0 dBZ도 그림 점선으로 함께 보였습니다.

**Q3.** 20 mm/h 비에서 1.1 km 아래를 못 본다면 호우의 지상 강수량은 어떻게 구하나요?
**A.** Ka 단일 주파수 위성 레이더의 공통 한계라 숨기지 않고 제안서에 적었습니다(feasibility.json 70줄). 임무의 1차 목적은 상층 구조(강수 꼭대기 높이, 수직 발달)로 호우 발달을 조기에 잡는 것이고, 지상 값은 해면 반사 신호가 비 때문에 얼마나 약해졌는지(경로적분감쇠, 20 mm/h에서 왕복 44 dB)로 거꾸로 추정하는 방법이 09번 9절 그림의 "해면 기준 측정 한계 42~49 dB"와 연결됩니다. 또 5·10 mm/h 비는 땅까지 다 보입니다(low = 0 km).
