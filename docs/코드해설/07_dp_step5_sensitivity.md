# 07. dp_step5_sensitivity.m 해설

> 담당: B   대상 파일: `dp/dp_step5_sensitivity.m` (177줄)   관련 결과 폴더: `out/dp_step5_sensitivity/` (key_sensitivity.json, cases.csv, summary.txt, fig_sensitivity.png, results.mat, run_info.txt)

## 1. 한 줄 역할
4단계(`dp_step4_realistic.m`)의 주 결과인 'DP 나우캐스트(Early 큐)' 하나를 받아, 위성 조건(정착 시간·큐 지연·기동 속도·지향 범위)을 하나씩 바꾼 여덟 경우의 호우 관측 이득(천저 고정 대비 배수)을 2023·2024·2025 시즌에 대해 다시 계산해 표·그림·json으로 저장한다.

용어 풀이(처음 나오는 것만):
- **민감도(sensitivity)**: 조건을 조금 바꿨을 때 결과가 얼마나 흔들리는지. 요구조건(정착 8초 이내, 큐 지연 30분 이내)이 '버틸 만한' 값인지 보는 것이 목적이다.
- **정착 시간(settle)**: 위성이 기울이는 동작을 끝낸 뒤 흔들림이 가라앉아 관측을 시작할 수 있을 때까지 걸리는 시간[초].
- **큐 지연(cueL, cue latency)**: 큐(어디를 볼지 알려 주는 천리안 2A 강수 장면)가 만들어져 위성에 올라가기까지의 시간[분]. 모의에서는 "통과 시작 cueL분 전에 끝난 30분 장면"을 큐로 쓴다.
- **기동 속도(slewRate)**: 빔(레이더가 보는 방향)을 기울이는 속도[°/s].
- **지향 범위(maxDeg)**: 천저(바로 아래)에서 좌우로 기울일 수 있는 최대 각[°].
- **천저 고정**: 기울이지 않고 바로 아래만 보는 비교 기준. 배수 1.0.
- **DP(동적계획법)**: 통과 한 번(관측창을 지나는 3~4분) 동안 1.5초 표본마다 어느 각도를 볼지, 기동으로 놓치는 표본까지 계산해 보상 합이 최대인 경로를 고르는 방법(01번 dpPlan 절 참고).

## 2. 흐름 (입력 → 처리 → 출력)
| 단계 | 하는 일 | 쓰는 함수·변수 | 나오는 것 |
|---|---|---|---|
| 준비 | 공용 함수 묶음과 기본 매개변수를 읽고 가짜 큐 오차를 끈다. 4단계가 만든 기준 학습 표를 읽는다 | `kre_lib`, `L.params`, `P0.pDet/posSd/velSd`, `calib_early_2023.mat` → `calib0` | `P0`, `calib0` |
| 조건표 | 여덟 경우의 이름·정착·큐 지연·기동 속도·지향 범위를 구조체 배열로 적는다 | `cs`, `nC = 8` | 조건 목록 |
| 자료 읽기 | 해마다 IMERG Final(진실)과 Early(큐)를 읽고 붙인다 | `L.loadSeason`, `L.attachCue` | `D` (채점은 Final, 큐는 Early) |
| 재학습 | 2023에서만, 큐 지연이 15분이 아닌 경우(30·45분)는 학습 표를 나이 1~4칸으로 다시 만든다 | `Pc.lags = 1:4`, `L.calibrate` | `calib{c}` |
| 궤도·통과 | 궤도 위상 8개마다 시즌 전체를 전파해 관측창 통과 목록을 만든다 | `L.orbitPasses`, `nPass` | `passes` |
| 천저 채점 | 통과마다 빔각 0 고정 계획을 채점한다 (모든 경우의 공통 분모) | `L.evaluate`, `nadir`, `dayN` | 천저 호우 프로파일 수 |
| 경우별 계획·채점 | 경우마다 매개변수를 바꿔 보상표 → DP 경로 → 채점 | `L.rewardGrid`, `L.dpPlan`, `L.evaluate`, `heavy`, `dayH`, `nMove` | 경우별 호우 프로파일 수, 기동 횟수 |
| 집계 | 위상 합의 비(배수), 날짜 부트스트랩 95% 신뢰구간, 기준 대비, 통과당 기동 | `gain`, `ci`, `rel`, `movePerPass` | 숫자 표 |
| 출력 | 화면 표, 그림 1장, summary/cases/json/mat/run_info, run_log 한 줄 | `bar`, `errorbar`, `writetable`, `jsonencode`, `logRun` | `out/dp_step5_sensitivity/*`, `out/run_log.csv` |

## 3. 절별 해설

### 3.1 머리말과 준비 (줄 1~29)
```matlab
clear; close all;
here = fileparts(mfilename('fullpath'));
outDir = fullfile(here, '..', 'out', 'dp_step5_sensitivity');
if ~exist(outDir, 'dir'), mkdir(outDir); end
tRun = datetime('now');
tic;
L = kre_lib();
P0 = L.params();
P0.pDet = 1;  P0.posSd = 0;  P0.velSd = 0;      % Early 큐: 가짜 오차 끔 (4단계 Pe와 같음)
S = load(fullfile(here, '..', 'out', 'dp_step4_realistic', 'calib_early_2023.mat'));
calib0 = S.calibE;                               % 기준 조건의 학습 표 (4단계와 같은 것)
```
줄 1~15의 주석은 이 파일의 설계 메모다. 핵심 문장은 "기준 조건은 4단계와 같아야 한다 → 같은 숫자가 나오는지 확인"(줄 6)이다. `kre_lib()`는 함수 손잡이(handle) 묶음 `L`을 돌려주고, `L.params()`가 기본 매개변수 `P0`(고도 550 km, 경사 45°, 지향 ±10°, 격자 1°, 기동 1.5°/s, 정착 4초, 큐 지연 15분, lags [1 2] 등. 01번 params 절 참고)를 만든다. 큐가 실제 Early 자료이므로 3단계에서 쓰던 가짜 오차 세 개(핵을 못 알아볼 확률 `pDet`, 위치오차 `posSd`, 속도오차 `velSd`)를 끈다. 이것은 4단계의 `Pe`와 똑같은 설정이다(`dp_step4_realistic.m` 줄 35). 학습 표 `calib0`는 4단계가 2023 자료로 만들어 저장한 것을 그대로 읽는다. 그래서 **이 파일은 4단계를 먼저 돌려 둬야 돌아간다.**

### 3.2 조건 목록 (줄 31~42)
```matlab
cs = struct('name', {'기준 (정착 4 s, 큐 15분)', '정착 2 s', '정착 8 s', '큐 지연 30분', '큐 지연 45분', '기동 1°/s', '지향 ±3°', '지향 ±5°'}, ...
            'settle', {4, 2, 8, 4, 4, 4, 4, 4}, 'cueL', {15, 15, 15, 30, 45, 15, 15, 15}, ...
            'slewRate', {1.5, 1.5, 1.5, 1.5, 1.5, 1, 1.5, 1.5}, 'maxDeg', {10, 10, 10, 10, 10, 10, 3, 5});
nC = numel(cs);
years = [2023 2024 2025];
nY = numel(years);  nDay = 122;
heavy = zeros(nY, P0.nPhase, nC);                % 시즌 호우 프로파일 (DP)
nadir = zeros(nY, P0.nPhase);                    % 천저 고정
dayH  = zeros(nY, nDay, nC);  dayN = zeros(nY, nDay);
nMove = zeros(nY, nC);  nPass = zeros(nY, 1);
calib = cell(1, nC);
```
`struct('name', {...}, 'settle', {...}, ...)`처럼 값을 중괄호 셀로 주면 길이 8짜리 구조체 배열이 된다. `cs(4).cueL`은 30, `cs(7).maxDeg`는 3이다. 각 경우는 **한 가지만** 기준에서 바꾼다(한 번에 하나씩 바꿔야 어느 조건이 얼마나 영향을 주는지 분리해서 볼 수 있다). 결과 그릇은 해(3) × 궤도 위상(8) × 경우(8) 크기의 `heavy`, 날짜별 합 `dayH`(122일 = 6~9월), 기동 횟수 `nMove`, 통과 수 `nPass`다. `nadir`·`dayN`에는 경우 차원이 없다. 천저 고정은 정착·큐·기동·범위와 무관하므로 한 번만 세면 된다.

### 3.3 해마다 자료 읽기와 학습 표 다시 만들기 (줄 44~60)
```matlab
for iy = 1:nY
    Df = L.loadSeason(years(iy), 'final');
    De = L.loadSeason(years(iy), 'early');
    D = L.attachCue(Df, De);
    clear De;
    if iy == 1
        for c = 1:nC
            if cs(c).cueL == 15
                calib{c} = calib0;
            else
                Pc = P0;  Pc.cueL = cs(c).cueL;  Pc.lags = 1:4;
                calib{c} = L.calibrate(D, Pc, 'nowcast', 2023);
            end
        end
    end
```
`loadSeason`이 한 시즌(6~9월, 30분 장면 5,856개)을 읽고, `attachCue(Df, De)`는 "채점은 Final(진실), 큐는 Early(운용 때 쓸 수 있는 거친 자료)"가 되도록 Early 장면을 `D.cuePr`로 붙인다(01번 attachCue 절 참고). 학습(큐 강도 → 실제 호우 확률 표 만들기)은 첫 해 2023에서만 한다. 큐 지연이 15분인 경우는 4단계 표를 그대로 쓰고, 30·45분인 경우만 **표의 열(나이)을 1~4칸으로 늘려** 새로 만든다. 이유: 큐 장면이 관측보다 몇 칸(30분 단위) 앞서는지가 큐 지연에 따라 달라지기 때문이다. 숫자 예: 큐 지연 15분이면 큐 장면은 관측보다 30~60분(1~2칸) 앞서지만, 45분이면 60~90분(2~3칸) 앞선다(계산은 5절 지적 2). 기본 표는 열이 [1 2]뿐이라 3칸 뒤 확률이 없으므로 1:4로 다시 배운다. 큐 지연이 바뀌어도 `calibrate` 자체는 `cueL`을 쓰지 않고 `lags`만 쓴다(01번 calibrate 절 참고).

### 3.4 통과마다 여덟 경우로 계획하고 채점 (줄 61~85)
```matlab
    for ip = 1:P0.nPhase
        passes = L.orbitPasses(D, P0, ip);
        nPass(iy) = nPass(iy) + numel(passes);
        for kp = 1:numel(passes)
            G = passes{kp};
            seed = years(iy) * 1e5 + ip * 1e4 + kp;           % 4단계와 같은 씨앗
            iday = min(floor(G.ts / 86400) + 1, nDay);
            E0 = L.evaluate(G, D, P0, struct('cb', zeros(size(G.tq)), 'valid', true(size(G.tq))));
            nadir(iy, ip) = nadir(iy, ip) + E0.heavy;
            dayN(iy, iday) = dayN(iy, iday) + E0.heavy;
            for c = 1:nC
                Pc = P0;  Pc.settle = cs(c).settle;  Pc.cueL = cs(c).cueL;  Pc.slewRate = cs(c).slewRate;  Pc.maxDeg = cs(c).maxDeg;
                if cs(c).cueL ~= 15, Pc.lags = 1:4; end
                [Rw, th] = L.rewardGrid(G, D, Pc, 'nowcast', RandStream('mt19937ar', 'Seed', seed), calib{c});
                plan = L.dpPlan(Rw, th, Pc);
                E = L.evaluate(G, D, Pc, plan);
```
궤도 위상(시즌 시작 때 위성이 궤도 어디에 있었나) 8개마다 시즌 전체를 전파해 관측창(북위 28.5~39.5°, 동경 119.5~131.5°, '넓힌 해역') 통과 목록을 만든다. 통과 하나 `G`에는 1.5초 간격 표본의 위치·시각이 들어 있다. 먼저 **천저 고정**(빔 오프셋 `cb` 전부 0, 모든 표본 유효)을 채점해 분모를 쌓고, 그 다음 경우마다 `Pc = P0`로 복사본을 만들어 네 값만 바꾼 뒤 보상표 `Rw`(표본 × 빔각, 01번 rewardGrid 절) → DP 경로 `plan`(01번 dpPlan 절) → 실제 Final 자료로 채점 `E`를 한다. MATLAB 구조체는 값 복사라 `Pc`를 고쳐도 `P0`는 안 바뀐다. 씨앗은 4단계와 같은 식(2024년 위상 3의 7번째 통과 → 2024×100000 + 30000 + 7 = 202,430,007)이지만, 가짜 오차를 껐으므로 사실 난수가 결과에 안 들어간다(5절 지적 6). `iday`는 통과 시작 시각(시즌 시작부터의 초)을 하루 86,400초로 나눠 몇째 날인지 구한 것으로, 뒤의 부트스트랩에 쓴다.

### 3.5 집계: 배수와 날짜 부트스트랩 신뢰구간 (줄 87~100)
```matlab
gain = squeeze(sum(heavy, 2)) ./ sum(nadir, 2);  % nY × nC
ci = zeros(nY, nC, 2);
for iy = 1:nY
    rs = RandStream('mt19937ar', 'Seed', 200 + years(iy));
    bs = zeros(2000, nC);
    for b = 1:2000
        pick = randi(rs, nDay, nDay, 1);
        bs(b, :) = sum(squeeze(dayH(iy, pick, :)), 1) / sum(dayN(iy, pick));
    end
    ci(iy, :, :) = reshape(prctile(bs, [2.5 97.5])', [1 nC 2]);
end
movePerPass = nMove ./ nPass;
rel = gain ./ gain(:, 1);                        % 기준 조건 대비
```
배수 `gain` = (8개 위상에서 DP가 본 호우 프로파일 수의 합) ÷ (천저 고정이 본 수의 합). 위상 평균의 비와 같다. **부트스트랩**(bootstrap)은 "122일 중 122일을 중복을 허용해 무작위로 다시 뽑아" 배수를 다시 계산하는 일을 2,000번 반복하고, 그 분포의 아래 2.5%·위 97.5% 지점을 95% 신뢰구간으로 삼는 방법이다. 날짜 단위로 뽑는 이유는 같은 날 통과들은 같은 비를 보므로 서로 독립이 아니기 때문이다. 씨앗 `200 + 해`는 해마다 따로 두어 해를 추가해도 다른 해 값이 안 바뀌게 한다. 여덟 경우가 **같은 날짜 뽑기**를 공유하므로 경우 간 비교가 짝지어진(paired) 비교가 된다. `rel`은 1열(기준) 대비 비율: 2024년 큐 30분이면 1.9288 ÷ 2.0385 = 0.946.

```matlab
    'nadirHeavyPerSeason', (sum(nadir, 2) / P0.nPhase)', 'params', rmfield(P0, 'C'));
```
다섯 파일에 같은 숫자를 다른 모양으로 적는다. `summary.txt`는 사람이 읽는 표(조건 한 줄에 3개 해 × 5개 값), `cases.csv`는 조건 × 해 = 24행짜리 긴 표(조건이 바깥 반복, 해가 안쪽 반복이라 1~3행이 기준 조건의 2023·2024·2025), `key_sensitivity.json`은 다른 프로그램(제안서 생성 파이썬)이 읽기 좋은 형식, `results.mat`은 날짜별 원자료까지 포함한 MATLAB 저장본, `run_info.txt`는 실행 시각·MATLAB 버전·매개변수. `compose`에 3×5 행렬을 주면 행마다 서식 하나를 채워 "2023 배수, 2023 CI하한, …"이 세 줄 나오고 `strjoin`이 이어 붙인다. 마지막 `logRun`은 `out/run_log.csv`에 2024/2025 대표 숫자를 한 줄 덧붙인다(`ix` 손잡이가 이름으로 열 번호를 찾는다).

## 4. 핵심 가정 3개
1. **한 번에 하나씩 바꾼다** — 두 조건을 같이 바꾸면 어느 쪽 영향인지 나눌 수 없어서. 깨지면(예: 실제 위성이 정착 8초·큐 45분·1°/s를 동시에 겪으면) 이득은 여기 적힌 값보다 더 떨어질 수 있다. 이 파일은 그 조합을 계산하지 않았다.
2. **기준 조건은 4단계와 완전히 같다**(매개변수·씨앗·궤도 위상·학습 표) — 그래야 8개 막대 중 1번이 4단계 숫자를 그대로 재현하고, 나머지 7개를 그 숫자와 비교할 수 있다. 깨지면 "기준 대비 93%" 같은 비교가 의미를 잃는다. 실제로 `cases.csv` 기준 행 2.0778/2.0385/2.0545는 `out/dp_step4_realistic/methods.csv`의 'DP 나우캐스트(Early 큐)' 2.0778/2.0385/2.0545와 소수점 끝까지 같다(5절 지적 1).
3. **큐 지연이 길어지면 학습 표만 다시 배우면 된다**(궤도·채점은 그대로) — 큐 지연은 "몇 칸 전 장면을 보느냐"로만 모형에 들어간다. 깨지면(예: 지연이 길어질수록 이동 벡터 추정도 나빠지는 효과)은 모형 밖이라 45분 결과가 실제보다 낙관적일 수 있다. 또 2023 한 해로 배운 표를 2024·2025에 그대로 쓴다는 4단계의 가정을 그대로 물려받는다.

## 7. 본선 예상 질문 3개와 답
**Q1.** 왜 ±10°인가요? 큐브위성이면 ±5°가 자세 제어에 훨씬 쉬울 텐데요.
**A.** 실제 2024·2025 강수 자료로 계산하면 ±5°는 1.45/1.44배, ±3°는 1.21/1.23배에 그치고 ±10°라야 2.04/2.05배가 됩니다(`cases.csv`). 호우 세포가 위성 궤적 바로 아래에 올 확률이 낮아 이득의 대부분이 6~10° 기울인 관측에서 나오며(4단계), ±5°면 이득의 70%를 잃습니다. 그래서 ±10°를 요구조건으로 두고 시스템 버짓(해면 오염 최저 고도 약 3 km 등)을 그 각도에서 계산했습니다.

**Q2.** 천리안 산출물 처리에 20분이 걸린다는데, 모의는 큐 지연 15분 기준 아닌가요? 실제로는 30분이 넘을 텐데요.
**A.** 그래서 30분과 45분을 따로 계산했습니다. 30분이면 1.93/1.91배로 15분일 때의 93% 이상이 남고, 45분이어도 1.81/1.83배입니다. 지연이 길어지면 학습 표도 그 지연(60~90분 앞선 장면)에 맞춰 다시 배워 공정하게 비교했고, 요구조건은 30분 이내, 목표는 15분으로 두었습니다.

**Q3.** 정착 2초와 8초, 기동 1°/s와 1.5°/s의 차이가 신뢰구간(±0.25) 안에 들어오는데, 그러면 이 민감도 분석이 아무것도 못 보여 주는 것 아닌가요?
**A.** 그게 바로 보여 주려던 결론입니다. 여덟 경우가 같은 날짜 뽑기를 공유하는 짝지어진 비교라, 기준 대비 비율(정착 8초 0.99, 1°/s 0.98~1.00)이 "자세 성능 요구를 느슨하게 잡아도 이득이 거의 안 깎인다"는 근거가 됩니다. 반면 지향 범위(±3°·±5°)는 신뢰구간이 전혀 겹치지 않을 만큼 크게 떨어지므로, 설계에서 양보하면 안 되는 조건과 양보해도 되는 조건을 구분해 줍니다.

2. 통과 시작 시각 ts에서 45분을 빼면 큐 시각이다. 큐 시각이 들어 있는 30분 칸은 아직 안 끝났으므로 그 앞 칸을 쓴다(`cueSlot`). ts가 자기 칸의 뒤쪽 절반(30분 중 15분 이후)에 있으면 큐 시각은 1칸 앞 칸에 떨어져 그 앞 칸, 즉 2칸 앞 장면을 쓰고(칸 차이 2), 앞쪽 절반에 있으면 큐 시각이 2칸 앞 칸에 떨어져 3칸 앞 장면을 쓴다(칸 차이 3). 장면의 가운데 시각 기준으로 큐는 관측보다 60~90분 앞선다. 기본 학습 표는 열이 1·2칸뿐이라 3칸 열이 없으므로 1~4칸으로 다시 배운다.
3. 1.91166848 ÷ 2.05452563 = 0.9305 → `relToBaseline` 0.930467과 일치. 93.05%이므로 "93% 이상"은 간신히 맞다(2024년은 94.6%). 2023 학습 해는 91.5%이지만 제안서는 검증 해만 인용한다.
