# 04. dp_step3_validate.m 해설

> 담당: B   대상 파일: `dp/dp_step3_validate.m` (212줄)   관련 결과 폴더: `out/dp_step3_validate/` (summary.txt, key_dp.json, methods.csv, passes.csv, results.mat, fig_dp_gain.png, fig_dp_bands.png, run_info.txt)

> 참고: 이 파일의 `years = [2023 2024]`다. 2023은 1단계에서 학습 표를 만든 해(학습), 2024는 처음 보는 해(검증)다. 2025년까지 넣고 큐를 IMERG Early로 바꾼 것은 다음 단계 `dp/dp_step4_realistic.m`이고, 저장된 결과(`run_info.txt`, 2026-10-20 실행, 168 s)도 2023·2024 두 해다.

## 1. 한 줄 역할
2023년에 학습한 "큐 강도 → 실제 호우 확률" 보정표(`out/dp_step1_train/calib_2023.mat`)를 받아, 2023·2024 장마 시즌(6~9월)의 모든 위성 통과에 다섯 가지 지향 방식을 똑같은 조건으로 적용해 호우 관측 수와 천저 고정 대비 배수, 날짜 단위 부트스트랩(복원추출로 흔들어 보는 통계 기법) 95% 신뢰구간을 계산해 표·그림·json으로 저장한다.

## 3. 절별 해설

### 3.1 준비: 학습 표 불러오기 (줄 16~27)
```matlab
L = kre_lib();
P = L.params();
S = load(fullfile(here, '..', 'out', 'dp_step1_train', 'calib_2023.mat'));
calibN = S.calibN;  calibP = S.calibP;
```
`kre_lib()`는 함수 묶음을 구조체 `L`로 돌려주고(01번 문서), `P`에는 궤도·안테나·큐 오차 같은 매개변수가 들어 있다(01번 3.1절). 그다음 1단계가 만든 보정표 두 개를 읽는다. `calibN`은 큐 장면을 이동 벡터로 옮겨 쓰는 "나우캐스트(초단기 예측)"용, `calibP`는 장면을 그대로 두는 "위치고정"용 표다. 두 표는 모두 2023 자료로만 만든 것이라(`calib.year = 2023`), 2024에 적용하면 "처음 보는 해"에 대한 검증이 된다. 이 파일 안에서는 `L.calibrate`를 다시 부르지 않는다는 점이 학습·검증 분리의 핵심이다.

### 3.2 비교 틀: 방식 5개와 누적 상자 (줄 29~40)
```matlab
years   = [2023 2024];
methods = ["천저 고정", "기존 방식(호우 표적)", "DP(위치고정)", "DP(나우캐스트)", "DP(완벽 정보, 상한)"];
mets    = ["호우 프로파일", "강수 프로파일", "호우 세포", "±3° 안 호우", "관측 표본", "전체 표본"];
nDay  = 122;
tot   = zeros(nY, P.nPhase, nM, nK);            % 시즌 합계
band  = zeros(nY, nM, 3);                       % 각도대별 호우 표본
dayH  = zeros(nY, nDay, nM);                    % 날짜별 호우 표본 → 부트스트랩용
```
방식 순서가 곧 번호다: 1 = 천저 고정(기준, 배수 1.00), 2 = 기존 방식, 3 = DP 위치고정, 4 = DP 나우캐스트(제안 방식), 5 = DP 완벽 정보(기동 제약 안에서의 상한). 이 번호는 뒤의 `plans{m}`, `fracOr`(4번÷5번), `bandGain(:,4,:)`, `passes.csv` 열 순서까지 모두 같은 약속으로 쓰인다. 지표 6개 중 "호우 프로파일"(10 mm/h 이상인 비를 본 1.5초 표본 수)이 주 지표다. `nDay = 122`는 6~9월 날짜 수(30+31+31+30)로, 뒤의 날짜 단위 부트스트랩에서 상자 개수가 된다. `tot`는 해 × 궤도 위상(8개) × 방식 × 지표의 4차원 합계 상자다.

### 3.3 시즌 반복: 통과마다 계획 5개 만들기 (줄 43~59)
```matlab
G = passes{kp};
seed = years(iy) * 1e5 + ip * 1e4 + kp;          % 방식마다 같은 씨앗 → 같은 큐 오차
plans{1} = struct('cb', zeros(size(G.tq)), 'valid', true(size(G.tq)));
plans{2} = L.greedyPlan(G, D, P, 'nowcast', RandStream('mt19937ar', 'Seed', seed));
[Rw, th] = L.rewardGrid(G, D, P, 'persist', RandStream('mt19937ar', 'Seed', seed), calibP);
plans{3} = L.dpPlan(Rw, th, P);
[Rw, th] = L.rewardGrid(G, D, P, 'nowcast', RandStream('mt19937ar', 'Seed', seed), calibN);
plans{4} = L.dpPlan(Rw, th, P);
[Rw, th] = L.rewardGrid(G, D, P, 'oracle', [], []);
plans{5} = L.dpPlan(Rw, th, P);
```
`L.loadSeason`이 한 해의 IMERG(위성 강수 추정 자료, 0.1°·30분 격자)를 읽고, `L.orbitPasses`가 궤도 위상 하나로 시즌을 전파해 관측창(북위 28.5~39.5°, 동경 119.5~131.5°) 통과 목록을 만든다(01번 3.3절). 통과 `G` 하나마다 계획 5개를 만든다. 1번은 빔각 `cb = 0`(천저)으로 고정. 2번 기존 방식은 큐 장면에서 10 mm/h 이상 국지 최대점을 표적으로 하나씩 찍는다(01번 3.6절). 3·4번은 `rewardGrid`가 만든 (시각 × 빔각) 보상표 `Rw`를 `dpPlan`이 동적계획법(작은 문제의 최적해를 이어 붙여 전체 최적 경로를 찾는 방법)으로 푼다(01번 3.4·3.5절). 5번은 큐 대신 실제 강수를 그대로 보상표로 쓰므로 "기동 제약 안에서 가능한 최대"다.

씨앗(seed) 값은 해·위상·통과 번호를 섞은 정수다. 예: 2023년, 위상 3, 통과 57 → 2023×100000 + 3×10000 + 57 = 202,330,057. 같은 씨앗으로 `RandStream`을 새로 만들어 2·3·4번에 넘기므로, 세 방식은 똑같은 가짜 큐 오차(호우 핵을 못 알아보는 확률 `pDet` 0.72, 위치오차 3 km, 속도오차 2 m/s; `cueScene`, 01번 3.4절)를 본다. 즉 방식 간 차이는 "계획을 짜는 법"의 차이만 남는다.

### 3.4 채점과 누적 (줄 60~77)
```matlab
iday = min(floor(G.ts / 86400) + 1, nDay);
for m = 1:nM
    E = L.evaluate(G, D, P, plans{m});
    r(m, :) = [E.heavy, E.rain, E.cells, E.heavyNear, E.valid, E.n];
    band(iy, m, :) = band(iy, m, :) + reshape(E.heavyBand, [1 1 3]);
    dayH(iy, iday, m) = dayH(iy, iday, m) + E.heavy;
end
ub = L.heavyInSwath(G, D, P);
nMove(iy, ip, :) = nMove(iy, ip, :) + reshape([plans{2}.nTargets, plans{4}.nMoves], [1 1 2]);
tot(iy, ip, :, :) = tot(iy, ip, :, :) + reshape(r, [1 1 nM nK]);
```
`L.evaluate`는 계획이 가리킨 빔이 실제로 닿은 IMERG 칸 값을 읽어 센다(01번 3.7절). 기동 중(`valid = false`)인 표본은 NaN이 되어 세지 않는다. `G.ts`는 6월 1일 0시(UTC)부터 흐른 초이므로 86400으로 나눠 올리면 날짜 번호(1~122)가 된다. 호우 표본은 `tot`(위상별 시즌 합), `dayH`(날짜별 합, 위상은 모두 더함), `band`(0~3°, 3~6°, 6~10° 각도대별) 세 곳에 동시에 쌓인다. `heavyInSwath`는 "±10° 안 어딘가에 호우가 있었던 표본 수"로, 기동 제약마저 없다고 칠 때의 이론 상한이다. `rows`에는 통과 한 줄(해, 위상, 통과 번호, 시작 시각, 상한, 방식별 호우 수)이 쌓여 `passes.csv`가 된다.

### 3.5 집계: 위상 평균과 배수 (줄 79~87)
```matlab
mTot = squeeze(mean(tot, 2));                    % nY × nM × nK
gain = mTot ./ mTot(:, 1, :);
gH   = squeeze(tot(:, :, :, 1)) ./ squeeze(tot(:, :, 1, 1));   % 위상별 호우 배수
gMin = squeeze(min(gH, [], 2));  gMax = squeeze(max(gH, [], 2));
fracOr = squeeze(mTot(:, 4, 1)) ./ squeeze(mTot(:, 5, 1));      % DP(나우캐스트)가 상한의 몇 %
bandGain = band ./ band(:, 1, 1);
```
궤도 위상 8개는 "위성이 어느 시각에 어디서 출발했나"가 다른 8가지 가상 궤도이고, 결과는 그 평균이다. 그래서 `mTot`에 107.625처럼 소수가 나온다. `gain`은 **모든 방식을 1번(천저 고정)으로 나눈 값**이다. 예: 2023 DP(나우캐스트) 263.875 ÷ 천저 107.625 = 2.452배. `gH`는 위상 하나하나의 배수로, 그 최소·최대가 "[위상 범위]"로 찍힌다(2023 DP 나우캐스트 1.91~3.70). `fracOr`는 제안 방식이 완벽 정보 상한의 몇 %인지(2023: 263.875 ÷ 444.875 = 59.3%), `bandGain`은 각도대별 호우 표본을 천저 전체(천저는 모두 0°라 `band(:,1,1)`이 전체)로 나눈 값이다.

### 3.6 날짜 단위 부트스트랩 (줄 89~101)
```matlab
rsB = RandStream('mt19937ar', 'Seed', 7);
for iy = 1:nY
    X = squeeze(dayH(iy, :, :));                 % nDay × nM
    for b = 1:2000
        pick = randi(rsB, nDay, nDay, 1);
        s = sum(X(pick, :), 1);
        bs(b, :) = s / s(1);
    end
    ci(iy, :, :) = reshape(prctile(bs, [2.5 97.5])', [1 nM 2]);
end
```
"2.45배가 우연일 수도 있지 않나?"에 답하는 부분이다. 날짜 122개를 통째로 뽑되 복원추출(뽑은 날짜를 다시 넣고 뽑아 어떤 날은 두 번, 어떤 날은 0번)로 122개를 뽑고, 뽑힌 날짜들의 호우 합을 방식별로 더해 천저 합으로 나눈다. 이걸 2000번 하면 배수가 2000개 생기고, 그중 2.5%·97.5% 지점이 95% 신뢰구간이다. 표본 단위를 통과가 아니라 **날짜**로 잡는 이유는 같은 날의 통과들(위상 8개 × 하루 2~3회)이 같은 비구름을 보기 때문에 서로 독립이 아니기 때문이다. 씨앗 7로 고정했으므로 다시 돌려도 같은 구간이 나온다. 결과: 2023 DP(나우캐스트) 2.20~2.77, 2024 2.43~3.14(`methods.csv` ci95Low·ci95High).

## 4. 핵심 가정 3개
1. **큐는 IMERG Final에 가짜 오차를 섞어 만든 것이다** — 실제 운용 큐(천리안 2A·KIM)의 오차 통계가 아직 없어 호우 핵 인식률 0.72, 위치오차 3 km, 속도오차 2 m/s를 가정으로 넣었다. 깨지면(실제 큐가 더 거칠면) 이득이 줄어든다. 그래서 `summary.txt`에 "낙관적 상한"이라고 적었고, 4단계가 큐를 IMERG Early로 바꿔 2.04~2.08배를 얻었다(`out/dp_step4_realistic/summary.txt`).
2. **2023년에 배운 "큐 강도 → 호우 확률" 표가 2024년에도 통한다** — 장마 강수의 통계적 성질이 해마다 크게 다르지 않다고 보았다. 깨지면 2024 이득이 2023보다 뚜렷이 낮아져야 하는데, 결과는 2.45 → 2.73배로 떨어지지 않았다(두 해 신뢰구간이 겹침).
3. **날짜가 서로 독립인 표본이다** — 부트스트랩이 날짜를 단위로 뽑는다. 장마는 며칠씩 이어지는 비가 많아 완전히 독립은 아니므로, 신뢰구간이 실제보다 조금 좁게 나올 수 있다. 통과 단위로 뽑았다면 훨씬 더 좁게(과신) 나왔을 것이므로, 날짜 단위는 보수적인 쪽으로 고친 선택이다.

## 7. 본선 예상 질문 3개와 답
**Q1.** "2배라는 이득의 분모는 무엇인가요? 기존 방식보다 2배인가요?"
**A.** 분모는 "기울이지 않고 바로 아래만 보는 천저 고정"입니다(`gain = mTot ./ mTot(:,1,:)`). 기존 방식(큐의 호우 표적을 하나씩 찍는 스케줄러)도 같은 분모로 1.39/1.57배이므로, 기존 방식 대비로는 2.452/1.386 = 1.77배(2023), 2.727/1.569 = 1.74배(2024)입니다. 발표에서는 두 숫자를 함께 말합니다.

**Q2.** "2023으로 학습하고 2024가 더 높게 나왔는데, 과적합(학습 자료에만 맞춘 것)이 아니라고 어떻게 말할 수 있나요?"
**A.** 학습 표는 2023 자료만으로 만들었고 2024에는 손대지 않고 그대로 적용했습니다(`calib_2023.mat`, 이 파일은 `calibrate`를 부르지 않음). 2024가 2.73배로 2023의 2.45배보다 높지만 두 해의 95% 신뢰구간(2.20~2.77, 2.43~3.14)이 겹치므로 "더 좋아졌다"가 아니라 "처음 보는 해에도 떨어지지 않았다"로 읽습니다. 2024에 호우 자체가 많았던 것(천저 107.6 → 129.9개)도 한 이유입니다.

**Q3.** "큐도 IMERG Final이고 채점도 IMERG Final이면 답을 보고 문제를 푼 것 아닌가요?"
**A.** 큐는 관측 15분 전 시점에 이미 끝난 30분 칸만 쓰고(관측보다 30~60분 앞선 장면), 거기에 호우 핵 인식 72%·위치오차 3 km·속도오차 2 m/s를 섞어 "답"을 그대로 보지 않게 했습니다. 그래도 자료 출처가 같고 오차 모형이 이상적이라 낙관적 상한이라고 명시했고, 큐를 실제 거친 자료(IMERG Early)로 바꾼 4단계에서 2.04~2.08배, 임무 관측창에서는 2.1~2.4배로 약 2배가 유지됨을 확인했습니다.
